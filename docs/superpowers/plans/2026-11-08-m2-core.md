# M2: Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Core engine — registry, validator, headless resolver, pure board reducer with history + detour stacks, event bus, `serializeBoard()`, `getSystemPromptGuide()`, `getCapabilities()`.

**Architecture:** `core/` is pure TypeScript (no React, no DOM). Schemas from `schema/` are the only dependency. All state mutations happen in the pure reducer; the event bus is an observer pattern.

**Tech Stack:** TypeScript strict, Zod, `fast-deep-equal` for state comparison, Vitest.

**Spec:** `dreamer-genui/AGENTS.md` sections 7.1 (board state/reducer), 7.3 (registry), 7.5 (attachment layout), 8 (generators).

---

## Global Constraints

- `core/` package: zero React imports, zero DOM APIs
- `BoardState`, `Detour`, `BoardSnapshot` are plain TypeScript interfaces
- The reducer is pure: `(state, op) → state` with no side effects
- Event bus is `Set<(event: UIEvent) => void>` — observer, not a class
- Generator functions are `async` only because they may load plugin manifests; they do not import React
- All errors emitted by the resolver/bus use `ErrorCodeSchema` from `schema/errors`
- Streaming: `applyPartial(reply)` must be idempotent — key by `op.index + node.id`

---

## Review Focus

1. **Idempotent partial application** — same partial applied twice produces same state
2. **Duplicate node ID** — rejected with `duplicate-id` error at reducer level
3. **Bad target** — `attach` to non-existent `NodeRef` emits `bad-target` error
4. **Depth-exceeded** — `attach` at depth 3 is rejected with `depth-exceeded`
5. **History on replace** — current board pushed to history before replace, not lost

- [ ] **Step 2: Write `EventBus`**

```ts
// events.ts
import type { UIEvent } from '../schema/events';

export class EventBus {
  private listeners = new Set<(event: UIEvent) => void>();

  subscribe(fn: (event: UIEvent) => void): () => void {
    this.listeners.add(fn);
    return () => this.listeners.delete(fn);
  }

  emit(event: UIEvent): void {
    for (const fn of this.listeners) fn(event);
  }
}
```

## Task 5: Board Reducer

**Files:**
- Create: `packages/dreamer-genui/src/core/reducer.ts`

**Pure reducer: `boardReducer(state, op): BoardState`**

Ops:
- `append`: add blocks to `nodes` (after optional `after` id position)
- `attach`: create a `Detour`, add blocks under the target; increment detour depth
- `replace`: push current state to `history`, reset nodes to new blocks
- `update`: merge `props` into existing node's block
- `remove`: delete node from `nodes`

**Key invariants:**
- `nodes` is `Record<NodeId, Node>` (ordered by insertion)
- `history` is `BoardSnapshot[]` (max 50 entries to prevent memory leak)
- `detours` max length 2; `replace` clears detours
- `back()` pops history, restores nodes + title
- Return a **new state object** (immutable, no mutations)

- [ ] **Step 1: Write boardReducer(state, op): BoardState**

```ts
// reducer.ts
export function boardReducer(state: BoardState, op: Op): BoardState {
  switch (op.op) {
    case 'append': return applyAppend(state, op);
    case 'attach': return applyAttach(state, op);
    case 'replace': return applyReplace(state, op);
    case 'update': return applyUpdate(state, op);
    case 'remove': return applyRemove(state, op);
  }
}

export function back(state: BoardState): BoardState { ... }
```

## Task 6: Resolver (headless, streaming-tolerant)

**Files:**
- Create: `packages/dreamer-genui/src/core/resolver.ts`

**BoardResolver class:**
- `state: BoardState` (current)
- `errors: LibraryError[]` (accumulated)
- `applyOps(reply: Reply, onEvent, onError)` — apply full reply
- `applyPartial(partial: PartialReply, onEvent, onError)` — apply partial (idempotent)
- `applyFinal(reply: Reply, onEvent, onError)` — finalize after partials
- `back()` — history back

**Streaming idempotency:** key partial state by `{opIndex}_{nodeId}`. Same partial applied twice produces identical intermediate state.

**Flow per op:**
1. Validate op (validator.ts)
2. If error: emit error, do not update state
3. Reduce state (reducer.ts)
4. If unknown type (resolver sees it after reduce): emit `unknown-type` error
5. Emit events (from op's effects — e.g., focusable clicked)
