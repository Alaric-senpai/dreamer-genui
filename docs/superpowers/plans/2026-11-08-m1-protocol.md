# M1: Protocol Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete Zod schemas for all protocol types (envelope, ops, blocks, figures, inline marks, motion, events, errors), JSON Schema export, all fixtures (valid and invalid), and pass all tests.

**Architecture:** `dreamer-genui` is a pnpm monorepo. M1 produces the `schema` package (server-safe, no React) as the foundation for all later milestones. All Zod schemas live here, inferred TypeScript types exported alongside. JSON Schema is derived from Zod and exported for tool-call schemas.

**Tech Stack:** TypeScript (strict), Zod v4, `zod-to-json-schema` for JSON Schema export, Vitest for tests.

**Spec:** `dreamer-genui/AGENTS.md` sections 3 (scope), 5 (layout), 6 (protocol), 9 (generators).

---

## Global Constraints

- TypeScript `strict: true`; no `any` in public API
- Schema package (`dreamer-genui/schema`) must have zero React/DOM imports
- Every Zod schema has a corresponding inferred TypeScript type and JSON Schema export
- Fixture filenames match the spec exactly (`define-biology.json`, `attach-botany.json`, etc.)
- `v: 1` is the only accepted version; future schema versions require a migration plan

---

## Review Focus

1. **Streaming idempotency** — partial ops with same op index + node id produce identical intermediate states
2. **Duplicate node ID rejection** — same `id` appearing twice in a board must error with `duplicate-id`
3. **Depth-exceeded for attach** — depth 3 attach must be rejected with `depth-exceeded`
4. **Bad target rejection** — `attach` to a non-existent `NodeRef` must error with `bad-target`
5. **Fallback degradation** — unknown node type renders `alt` text without crashing, emits `unknown-type` error

- [ ] **Step 1: Write `envelope.ts` — Reply and versioning**

```ts
import { z } from 'zod';

// v versioning schema — only v:1 accepted
export const VersionSchema = z.literal(1);
export type Version = z.infer<typeof VersionSchema>;

// Reply envelope
export const ReplySchema = z.object({
  v: VersionSchema,
  ops: z.array(z.unknown()), // validated per-op in resolver
});
export type Reply = z.infer<typeof ReplySchema>;
```

- [ ] **Step 2: Write `ops.ts` — all operation types**

```ts
import { z } from 'zod';
import { BlockSchema, type Block } from './blocks';
import { NodeId, NodeRef } from './common';

// Common motion fields reused in marks and blocks
export const MotionFieldsSchema = z.object({
  order: z.number().optional(),
  delay: z.number().optional(),
  duration: z.number().optional(),
});

// Op: append
export const AppendOpSchema = z.object({
  op: z.literal('append'),
  blocks: z.array(BlockSchema),
  after: NodeId.optional(),
});

// Op: attach
export const AttachOpSchema = z.object({
  op: z.literal('attach'),
  to: NodeRef,
  blocks: z.array(BlockSchema),
  placement: z.enum(['right', 'left', 'above', 'below', 'overlay', 'inline']).optional().default('inline'),
  connector: z.enum(['line', 'arrow', 'bracket', 'none']).optional().default('none'),
  target: z.object({
    annotate: z.enum(['circle', 'underline', 'box', 'highlight', 'bracket', 'none']).optional(),
  }).optional(),
  mode: z.enum(['inline', 'drawer', 'spotlight']).optional().default('inline'),
});

// Op: replace
export const ReplaceOpSchema = z.object({
  op: z.literal('replace'),
  blocks: z.array(BlockSchema),
  title: z.string().optional(),
});

// Op: update
export const UpdateOpSchema = z.object({
  op: z.literal('update'),
  id: NodeId,
  props: z.record(z.unknown()),
});

// Op: remove
export const RemoveOpSchema = z.object({
  op: z.literal('remove'),
  id: NodeId,
});

// All ops union
export const OpSchema = z.discriminatedUnion('op', [
  AppendOpSchema,
  AttachOpSchema,
  ReplaceOpSchema,
  UpdateOpSchema,
  RemoveOpSchema,
]);
export type Op = z.infer<typeof OpSchema>;
```
